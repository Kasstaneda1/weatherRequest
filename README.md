# Weather App

Учебный проект. Небольшая страница, которая показывает погоду в выбранном городе: человек вводит название города, жмёт **Search** и видит текущую погоду. Если города нет или сервер ответил ошибкой, вместо погоды показываем ошибку.

Полный текст задания лежит в [TASK.md](TASK.md).
Макет: [Figma](https://www.figma.com/design/fwgYIR4OoE2eC3UGw5ZUWD/Untitled?node-id=298-36&t=XuZXvaSdNoDTykhD-0)

## Стек

Никаких фреймворков и сборщиков, только три файла:

| Файл | За что отвечает |
| :--- | :--- |
| `index.html` | разметка страницы |
| `styles.css` | оформление |
| `index.js` | логика: запрос к API, загрузка, вывод данных и ошибок |

Чтобы запустить, достаточно открыть `index.html` в браузере.

## Кто что делает

| Участник | Задача | Файлы |
| :--- | :--- | :--- |
| **Ибрагим** | Шапка и фон страницы | `index.html`, `styles.css` |
| **Улугбек** | Поле ввода города и кнопка Search | `index.html`, `styles.css`, `index.js` |
| **Михаил** | Область вывода погоды и ошибок | `index.html`, `styles.css`, `index.js` |

### Ибрагим, шапка и фон

Ты делаешь основу страницы, поэтому начинаешь первым.

- собрать скелет `index.html`: `<head>`, подключение `styles.css` и `index.js`
- найти и положить в `assets/` фоновую картинку: капли дождя на стекле, синевато-серая, снизу темнее. Подойдёт любая похожая с бесплатного стока, например Unsplash
- растянуть фон на весь экран: `background-size: cover`, `background-position: center`, `min-height: 100vh`
- шапка: полоса во всю ширину, высота 60px, полупрозрачная белая с размытием, снизу тонкая светлая линия
- заголовок **Weather App** по центру шапки, белый, жирный, 20px
- прописать в `styles.css` общие вещи: шрифт, `box-sizing: border-box`, сброс отступов у `body`, белый цвет текста по умолчанию
- оставить в разметке пустые блоки-заготовки для формы и для вывода, с готовыми `id` (список ниже)

### Улугбек, форма поиска

- поле ввода и кнопка стоят в одну строку по центру, отступ между ними 16px
- поле: скруглённое до овала, тонкая белая рамка, фон полупрозрачный, текст внутри белый
- кнопка **Search**: такой же овал, залита синим `#4A7DB5`, текст белый, рамки нет
- обработчик нажатия на кнопку
- если поле пустое, показать `alert` с просьбой ввести город, запрос при этом не отправлять
- пока идёт запрос: заблокировать кнопку и показать «Loading…» под формой
- когда ответ пришёл: разблокировать кнопку и убрать «Loading…»
- заблокированная кнопка должна выглядеть неактивной, например `opacity: 0.6` и `cursor: not-allowed`

### Михаил, вывод данных

- запрос к API OpenWeather
- очистка старых данных перед новым запросом
- отрисовка погоды: большая карточка, слева температура и название города, справа иконка погоды
- под ней ряд из двух карточек поменьше, в левой подпись FEELS LIKE и температура по ощущениям
- отрисовка ошибки: вместо карточек с погодой одна карточка с текстом. Заголовок красный `#E9564C`, крупный, по центру, под ним белым сообщение об ошибке
- все карточки одинаковые: полупрозрачный тёмно-синий фон с размытием, скругление 16px

## Общие точки в разметке

Чтобы код одного не ломал код другого, договорились об этих `id` заранее. Их придумывать заново не надо, просто используем как есть:

```html
<header class="header">...</header>

<form id="search-form">
  <input id="city-input" type="text" />
  <button id="search-btn" type="submit">Search</button>
</form>

<p id="loading">Loading…</p>

<div id="result"></div>
```

- `#search-form`, `#city-input`, `#search-btn`, `#loading` это зона Улугбека
- `#result` это зона Михаила
- `header` и всё, что вокруг, это зона Ибрагима

## Где макет расходится с API

Разобрали заранее, чтобы никто не залипал на этом в одиночку.

1. **В макете три иконки погоды, а API отдаёт одну.** В ответе лежит `weather[0].icon`, это один код вида `10d`. Три иконки в макете нарисованы просто для красоты. Рисуем одну, как и написано в пункте 8 задания.

2. **Вторая карточка в нижнем ряду пустая.** В макете её не заполнили. Предлагаю положить туда влажность или ветер, они оба есть в ответе: `main.humidity` и `wind.speed`. Если есть идея получше, говорите.

3. **Температура.** В макете градусы Цельсия, а API по умолчанию отвечает в Кельвинах. В адресе из задания параметра `units` нет, поэтому переводим прямо в коде:

   ```js
   const celsius = Math.round(kelvin - 273.15);
   ```

   Второй вариант, дописать `&units=metric` в адрес, тоже рабочий, но тогда мы отходим от текста задания.

4. **Адрес картинки в задании начинается с `http://`.** Пока открываем `index.html` с диска, это не мешает. Но если выложим страницу на хостинг с `https`, браузер такую картинку заблокирует. Проще сразу писать `https://openweathermap.org/img/w/${icon}.png`, по этому адресу всё то же самое.

5. **Мелочи из макета, которые повторять не надо.** В поле набрано «Colrado», это опечатка автора макета. «FEELS LIKE 26°» при 18° на улице тоже просто выдуманные числа. И заголовок в задании написан «Weather app», а в макете «Weather App», взяли вариант из макета.

## Как не мешать друг другу

Мы втроём правим одни и те же три файла, так что конфликты при слиянии почти неизбежны. Чтобы их было поменьше:

1. Первым свою часть вливает Ибрагим. Пока скелета страницы нет, остальным не за что зацепиться.
2. Дальше Улугбек и Михаил работают параллельно, каждый в своём блоке разметки.
3. В `styles.css` каждый пишет в свою секцию, помечаем комментарием:

   ```css
   /* === header (Ибрагим) === */
   /* === search form (Улугбек) === */
   /* === result (Михаил) === */
   ```

4. Чужие блоки не трогаем. Если что-то в чужой части мешает, пишем в чат команде, а не правим молча.

## Правила работы с git

**Пушить напрямую в `main` нельзя.** Ветка защищена, GitHub такой push отклонит. Это не ошибка и не сбой доступа, так задумано.

Работаем только через ветки и pull request:

```bash
# берём свежий main
git checkout main
git pull

# заводим свою ветку
git checkout -b feature/header

# работаем, коммитим
git add .
git commit -m "Add page header and background"

# отправляем ветку и открываем pull request
git push -u origin feature/header
```

Договорённости:

- одна задача, одна ветка, один pull request
- имена веток: `feature/header`, `feature/search-form`, `feature/result`
- перед началом работы всегда `git pull` в `main`, чтобы не разъехаться
- в описании pull request коротко пишем, что сделали

## Ключ от OpenWeather

**Ключ у каждого свой.** Он бесплатный, регистрация занимает пару минут, и так не придётся пересылать его друг другу в переписке.

Репозиторий публичный, поэтому **ключ в код класть нельзя**. По GitHub постоянно ходят боты, которые ищут именно такие ключи. Найденный ключ либо заблокируют, либо им начнёт пользоваться кто-то чужой. И просто стереть его потом не выйдет: старый коммит останется в истории, и достать ключ оттуда сможет любой.

Как делаем:

1. Заводим ключ на [openweathermap.org](https://openweathermap.org/api).
2. Копируем файл-образец и вписываем в него свой ключ:

   ```bash
   cp config.example.js config.js
   ```

3. Всё, `config.js` лежит в `.gitignore` и в репозиторий не попадёт.

Свежий ключ начинает работать не сразу. Если сразу после регистрации приложение отвечает ошибкой **401**, это нормально, ключ ещё не активировался. Иногда нужно подождать до пары часов.
